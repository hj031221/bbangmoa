🧭 빵지순례 경로 추천 — 알고리즘 설계 (단계별)

보조기능이지만 네가 직접 설계할 파트. 아주 기초부터 쉬운 말로 넓게 깔고 → 한 단계씩 같이 좁혀간다. (지금은 STEP 1: 알고리즘 지형 넓게 보기)

STEP 1 · 알고리즘을 넓게 깔아보자

"이름만 안다"는 상태 기준. 용어 나오면 바로 쉬운 말로 풀어줄게.

1.1 우리가 풀 문제 (한 문장)

여러 빵집(+주변 관광지)을 어떤 순서로 돌면 좋을지를, b) 실시간 교통을 반영한 이동시간으로 짧게 + c) 사람 덜 몰리는 쪽으로 추천한다. 이동수단은 차/도보(지도 API가 지원하는 형태 그대로).

1.2 '그래프'가 뭐냐 (제일 기초)

A— 7분 —B— 4분 —C
동그라미(A·B·C) = 노드(node) = 장소(빵집·관광지)
선 = 엣지(edge) = 두 장소 사이 길 · 선에 적힌 값 = 가중치(weight) = 이동시간/거리

"그래프 알고리즘"은 결국 이 동그라미·선 그림 위에서 길을 어떻게 고를까를 푸는 방법들이야. 빵집 지도가 딱 이 그림이고.

1.3 ⭐ 먼저 알 핵심: 지도 API가 이미 해주는 게 있다

"두 지점 사이 최단/최快 경로"는 카카오·네이버 지도 API가 이미 계산해줘 (도로망 + 실시간 교통 포함). 즉 우리가 Dijkstra 같은 걸 직접 안 짜도 돼. 지도 API를 "A→B 몇 분 걸려?"를 물어보는 계산기로 쓰면 됨.
→ 그럼 우리가 진짜 설계할 건: ① 여러 곳을 어떤 순서로 돌지(방문순서) ② 그 순서를 정할 때 취향·혼잡을 어떻게 점수에 섞을지(가중치).

그래도 Dijkstra/A* 같은 "최단경로" 알고리즘을 아래에 깔아두는 이유: 원리를 알아야 가중치를 어디에 어떻게 넣을지 감이 와. (그리고 지도 API 못 쓰는 상황 대비)

1.5 그래서 우리 방향 추천 (b+c)

① 거리/시간 = 카카오 길찾기(실시간 교통) ② 순서 = NN으로 짜고 → 2-opt로 다듬기 ③ 혼잡(c) = 비용에 패널티 더하기.
= 직접 짤 건 사실상 NN + 2-opt(아주 짧은 코드)뿐. 최단경로·실시간 교통은 지도 API가 해결. 곳이 적으면(≤10) Held-Karp로 "최적" 옵션도 가능.
정직한 빈칸: (c)혼잡의 데이터 출처가 아직 미정. 가게단위 실시간 혼잡은 무료 공개 데이터가 없음 → 후보: ⒜ 시간대 가정(영업시간·러시아워 룰) ⒝ 관광공사 지역 방문 추이/예측(#18/#21, 동네단위) ⒞ 자체 클릭/체크인 누적. STEP 4에서 이걸 정한다.

1.6 비용(가중치) 수식 — 자리부터 잡기

두 장소 i→j로 갈 때의 "비용"을 이렇게 둘 수 있어. (값·계수는 STEP 4~5에서 데이터 보고 채움)

cost(i→j) = α · 이동시간(i→j) ← 카카오 실시간 교통
         + β · 혼잡패널티(j, 시각) ← (c), 출처 STEP4
         − γ · 취향점수(j) ← 설문 결과(이미 있음)
         − δ · 영업가능(j, 시각) ← 관광공사 opentimefood

목표: 코스 전체 Σcost 최소 (= 짧고·안 붐비고·취향 맞고·열려있는 동선)
α,β,γ,δ = "각 요소를 얼마나 중요하게 볼지" 손잡이. 이거 튜닝이 네가 재밌어할 부분. 데이터 들어오면 같이 돌려보며 잡자.

1.7 다음 단계 로드맵

STEP 1
알고리즘 넓게 깔기 — 지금 여기. 지형·후보·우리 방향 잡음.
STEP 2
최단경로(Dijkstra/A*) 원리만 그림으로 깊이 — 가중치 감각 익히기.
STEP 3
방문순서(NN→2-opt→Held-Karp) 예시로 직접 돌려보기.
STEP 4
실시간(b)·혼잡(c) 데이터 출처 확정 + 패널티 설계.
STEP 5
수식 계수(α~δ) 확정 + 관광공사/카카오 데이터 연결.
STEP 6
지도 옆 코스 실제 구현·데모 (Polyline+순서+주변장소).
STEP 1 확인 질문 (네 방향대로 좁히게):
  • 1.3의 "지도 API가 최단경로는 해준다 → 우리는 순서+가중치만" — 이 프레임 OK? 아니면 최단경로도 직접 파보고 싶어?
  • 코스 규모 감: 보통 몇 곳 도는 코스로 생각해? (3~5곳이면 NN+2-opt로 충분, 10곳 넘으면 얘기 달라짐)
  • 혼잡(c)을 진짜 넣고 싶어, 아니면 일단 b(실시간 경로)부터 단단히? (혼잡은 데이터가 까다로워서)
