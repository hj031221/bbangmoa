▲ GitHub → Vercel 배포 가이드

레포 hj031221/bbangmoa 에 push → Vercel이 자동 빌드·배포. 팀 협업 + 1차 심사 제출용.

구조① 레포 연결② Vercel Import ③ 환경변수④ 브랜치⑤ 카카오 도메인 ⑥ 협업 흐름내가 해줄 수 있는 것문제 해결

전체 구조

로컬 코드git pushGitHub bbangmoa자동 감지Vercel 빌드·배포→공개 URL

이미 Vercel ↔ GitHub 연동이 되어 있으니(Lens 때 가입), 레포만 연결하면 push할 때마다 자동 배포돼. CLI 직접배포 불필요.

✅ 준비됨: 루트에 vercel.json(관광공사 /tourapi 프록시 + SPA 폴백) 생성 완료. 레포에 같이 올리면 배포본에서 관광공사 호출도 그대로 동작.

① 로컬 ↔ GitHub 레포 연결

⚠️ 친구와 만든 레포라 이미 파일이 있을 수 있음. 우리 스캐폴드와 충돌 방지를 위해 먼저 레포 상태를 확인하고 합치는 게 안전 — 이 부분은 코딩 채팅에서 신중히(아래 "내가 해줄 수 있는 것" 참고).
A
레포가 비어있다면 — 현재 폴더를 레포로 올리기 
cd C:\Users\user\관광공모전
git init
git remote add origin https://github.com/hj031221/bbangmoa.git
git checkout -b <작업브랜치>
git add .
git commit -m "init: 대전 빵집 지도 스캐폴드 + vercel 설정"
git push -u origin <작업브랜치>
B
레포에 이미 내용이 있다면 — 클론해서 거기에 옮겨 담기 (충돌 안전) 
git clone https://github.com/hj031221/bbangmoa.git
cd bbangmoa
git checkout <작업브랜치>        # 주어진 브랜치로
# (우리 src/, vercel.json 등을 이 폴더로 복사 후)
git add . && git commit -m "feat: 빵집 지도 스캐폴드" && git push
<작업브랜치> = 친구가 알려준 그 브랜치 이름으로 치환. 초대 수락(Collaborator) 되어 있어야 push 가능.

② Vercel에서 레포 Import

1
vercel.com/new → Import Git Repository → 목록에서 bbangmoa 선택
안 보이면 "Adjust GitHub App Permissions"로 레포 접근 권한 허용.
2
Framework: Vite 자동감지 확인 (Build npm run build · Output dist) → 그대로 두기.
환경변수는 ③에서 넣고 배포해도 되고, 이 화면에서 미리 넣어도 됨.

③ 환경변수 3개

.env는 레포에 안 올라가(보안). Vercel에 직접 입력. VITE_ 키는 빌드 시 박히므로 입력 후 재배포 필요.

프로젝트 → Settings → Environment Variables (Production 체크):

NameValue
VITE_KAKAO_JS_KEY카카오 JavaScript 키
VITE_KAKAO_REST_KEY카카오 REST API 키
VITE_TOUR_API_KEY관광공사 Decoding 인증키
입력 후 Deployments → 최신 → ⋯ → Redeploy (또는 아무 커밋 push).

④ 프로덕션 브랜치 설정

  • Settings → Git → Production Branch = 배포로 쓸 브랜치(예: main 또는 친구가 정한 브랜치).
  • 그 브랜치에 push/merge → 운영 URL 자동 갱신.
  • 다른 브랜치·PR → 각각 Preview URL 자동 생성(팀이 미리보기 공유하기 좋음).
"주어진 브랜치에서 작업"한다면: 그 브랜치를 Production으로 두거나, 작업브랜치는 Preview로 두고 검수 후 main에 merge하는 방식 중 택1. (⑥ 참고)

⑤ 카카오에 배포 도메인 추가

지도는 등록된 도메인에서만 떠. 배포 후 나온 주소를 추가:

1
Kakao Developers → 내 앱(빵모아) → 앱 → 플랫폼 키 → JavaScript 키 → "JavaScript SDK 도메인" 
https://(프로젝트명).vercel.app
Preview URL도 보여줄 거면 그 주소들도 줄바꿈으로 추가. localhost는 그대로 둠.

⑥ 협업 흐름 (권장)

작업브랜치 push→Preview URL 자동→팀 검수→main merge→운영 배포
  • 기능별 브랜치 → PR → Vercel이 PR마다 Preview 링크 댓글
  • 친구와 충돌 줄이려면 같은 파일 동시수정 피하고 작은 PR로
  • vercel.json·.env.example는 공유, .env는 각자 로컬

🤝 내가(Claude) 해줄 수 있는 연결

할 수 있음 (이 PC에 git 설치돼 있음):
  • git 초기화 · remote 연결 · 브랜치 생성 · 커밋 · push (자격증명이 PC에 저장돼 있으면)
  • vercel.json 등 배포 설정 파일 작성 (이미 함)
  • 레포 기존 내용과 우리 스캐폴드 충돌 없이 합치기
내가 못 하는 것 (네 몫):
  • Vercel 대시보드 로그인·Import 클릭·환경변수 입력 (네 계정)
  • 카카오 콘솔 도메인 등록 (네 계정)
  • GitHub 인증이 PC에 없으면 push 불가 — 토큰/Git Credential Manager 로그인 필요 (gh CLI는 이 PC에 없음)
