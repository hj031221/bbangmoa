## 1. 결론

develop의 설문 0단계는 **"구(district) 선택"** 하나뿐이라 **좌표가 없다**. 이걸 **우리 위치 질문(정밀 출발지: 프리셋 + GPS + 지도 직접 찍기)으로 그대로 교체**한다. 구를 프리셋에 매핑하는 게 아니라, **우리 개선판 질문을 통째로 넣는다.**

핵심 이유: 여기서 얻는 **정밀 좌표 `origin`이 설문 이후 결과에도 흐른다.** 즉 "오늘의 빵 → 지도 → (나중) 여행 도착지"가 **실제 내 위치 기준**으로 현실화된다. 구 단위(coarse)로는 이게 안 된다.

**이번 지시서는 origin 확보 + 설문 흐름 통합까지.** 경로/하루 코스·영업시간·로직 최종본은 범위 밖(§8).

## 3. 데이터 계약 (origin)

```text
origin = {
  lat, lng,             // 정밀 좌표
  label,                // "대전역" / "현재 위치" / "지도에서 선택"
  source: 'preset' | 'gps' | 'pick'
}
```
- store: `origin: null` 기본 + `setOrigin(origin)` + `resetAnswers`에 `origin:null`.
- **origin은 결과로 흐른다**: `MapResult`가 거리 계산·정렬·(추후)도착지 기준을 GPS/역 대신 **origin 우선**으로.

## 4. 상세 동작 명세 — LocationStep (설문 0단계 = 우리 질문 그대로)

제목: **"어디서 출발하세요?"** 세 방법 모두 제공:

### 4.1 프리셋 버튼 (regions.daejeon.origins)
```text
🚉 대전역(36.33184,127.43417) · 🚉 서대전역(36.31984,127.40287)
🚌 복합터미널(36.3505,127.4348) · 🚌 유성터미널(36.354,127.341)
🏛️ 시청(36.3504,127.3845) · 🏙️ 둔산(36.3515,127.3776)
```
클릭 → `setOrigin({...preset, source:'preset'})` → 다음 단계.

### 4.2 📍 현재 위치 사용 (GPS)
`useCurrentLocation` → 좌표 오면 `setOrigin({lat,lng,label:'현재 위치',source:'gps'})`. 거부/미지원 → "권한 필요" 안내 + 프리셋/지도 유도(앱 안 멈춤).

### 4.3 🗺️ 지도에서 직접 찍기 (이번 범위 포함)
- **대전 밖이든 안이든** 사용 가능. 작은 카카오맵 → 클릭 지점 `setOrigin({lat,lng,label:'지도에서 선택',source:'pick'})`.
- 확정 버튼으로 다음 단계.

### 4.4 SurveyFlow 통합
- step 0 = `<LocationStep onDone={()=>setStep(1)} />` (구 버튼 삭제).
- step≥1 = 기존 SURVEY 문항 그대로.
- 진행바 카운트 동일(0번 의미만 교체).

## 6. 결정됨 (A안 확정)

**빵집 검색을 구(district) 기반 → 위치(origin) 기반으로 전환.**
- 구 선택 UI 제거. 검색은 develop의 전 구 자동 루프(이미 있음)로 다 긁음.
- 결과 리스트를 **origin에서 가까운 순으로 정렬**(haversine). 사용자는 구를 안 고르고 "내 위치에서 가까운 빵집"을 봄.
- district state는 유지하되(호환) 검색 필터로는 안 씀.
