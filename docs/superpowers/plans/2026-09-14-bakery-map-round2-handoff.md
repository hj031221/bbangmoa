## 시안 vs 현재 화면 — 대조 결과

브라우저로 `/bread-map`을 직접 띄워 시안 이미지와 항목별로 비교했다.

### A. 이미 의도적으로 뺀 항목(재확인만, 손 안 댐)

- **영업 중 / 마감시간 표시**: 빵집 데이터에 `hours` 필드가 없어 1차 개편 때 제외 확정.
- **지도 핀 번호 매김**: `MarkerLayer.jsx`가 세밀하게 튜닝된 컴포넌트라 별도 검토 필요,
  1차 개편 범위 밖으로 명시.
- **상세 카드의 "코스에 담기" / "기록 남기기" 버튼**: 대전한바퀴 코스 개념과 연결되는
  신규 기능이라 1차 개편 범위 밖으로 명시.

### B. 미결정 — 순위 배지 (사용자가 "일단 보류, 프롬프트로 남겨달라"고 함)

시안은 전체/구필터 모드에서도 리스트 항목마다 원형 숫자 배지(1~5)를 붙이고, 그 번호가
지도 핀 번호와 일치한다. 현재 코드(`BakeryMapPage.jsx`)는 "최종 리뷰 6" 커밋에서 이걸
`nearbyMode`(근처 빵집, 거리순 정렬)에서만 보이게 뺐다 — 근거: "기본/구 필터/검색
목록의 순서는 찜 우선 + API 응답 순이라 번호를 달면 데이터가 뒷받침 못하는 랭킹을
암시한다"(`BakeryMapPage.jsx`의 해당 주석, `src/components/map/BakeryMapPage.jsx:234-236`
부근).

시안을 보면 이 번호가 "품질 순위"가 아니라 "리스트 항목 ↔ 지도 핀 대조용 인덱스"일
가능성이 높다 — 그렇다면 지도 핀 번호 매김(위 A 항목, 아직 범위 밖)과 묶어서 **같이**
처리하는 게 맞다: 리스트에만 번호를 붙이고 지도 핀은 안 붙이면 오히려 더 헷갈린다.

**다음 세션에서 결정할 것:**
- 순위 배지를 "랭킹"이 아니라 "인덱스"라는 의미로 명확히 하고 전체/구필터/검색 모드에도
  다시 붙일지, 아니면 지도 핀 번호 매김(MarkerLayer.jsx 작업)과 묶어서 한 번에 처리할지.
- 다시 붙이기로 하면: `BakeryMapPage.jsx`의 `{nearbyMode && <span className="rank">...}`
  조건(약 237번째 줄)에서 `nearbyMode &&`를 제거하되, 주석을 "랭킹 아님, 지도 핀과
  대조하는 인덱스"로 바꿔 다음 리뷰에서 같은 오해가 재발하지 않게 할 것.

### C. 보류 — 레이아웃 구조 차이 (사용자가 명시적으로 "다음 라운드로" 미룸)

시안은 1차 개편이 건드리지 않은, 더 근본적인 레이아웃 차이가 있다:

1. **검색창·구필터·리스트의 그룹핑**: 시안은 검색창 + 구필터 칩 + "이 지역의 빵집 N곳" +
   리스트가 지도 옆 **왼쪽 컬럼 하나**로 묶여 있다. 현재는 검색창·구필터 칩이 전체 폭
   헤더 아래 별도 줄로 떨어져 있고, 그 아래 3컬럼(지도/리스트/상세)이 온다.
2. **헤더/툴바 형태**: 시안의 "대전광역시 · 빵집 259곳"(위치핀 아이콘) + "목록 숨기기"는
   **지도 위에 떠 있는 작은 흰색 알약(pill) 버튼** 2개다(카운트는 지도 좌상단, 토글은
   지도 우상단). 현재는 페이지 전체 폭을 차지하는 골드색 `.result-header` 바 안에 같이
   들어 있다 — 훨씬 무겁고 다른 스타일.
3. **상세 카드**: 시안은 선택한 빵집 카드가 **지도 위에 겹쳐진 플로팅 카드**(지도
   우하단, 반투명 흰 배경 + 그림자)다. 현재는 지도/리스트와 나란한 **3번째 고정 컬럼**
   (`RecommendCard` — 사진 + "찜하기" 텍스트 버튼 + 태그 pill + 주소/전화, 세로로 긴
   사이드바 형태)이다.

이 세 가지는 서로 얽혀 있다(헤더를 플로팅 pill로 바꾸면 3컬럼 그리드 자체를 2단
구성으로 바꿔야 하고, 상세 카드를 컬럼에서 플로팅으로 바꾸면 `RecommendCard`의 내용
구성도 다시 짜야 한다) — 부분 수정보다 **레이아웃 전체를 시안 기준으로 다시 설계**하는
편이 나을 가능성이 높다. 다음 세션 시작 시 반드시 `superpowers:brainstorming`으로 사용자와
범위·우선순위(전부 다시 짤지, 헤더만 먼저 바꿀지 등)를 먼저 맞출 것 — 이 문서는 "무엇이
다른가"까지만 정리했고 "어떻게 다시 만들지"는 아직 사용자와 논의 전이다.
