## 발견 및 수정한 이슈

구현은 태스크 8개 각각 구현→리뷰 통과 후, 브랜치 전체를 대상으로 한 최종 리뷰(가장 유능한 모델로 진행)에서 아래 2건을 추가로 발견해 한 번에 수정했다.

- **[Critical] 관광지 성향 벡터가 173곳 중 14종류로만 뭉쳐 있었음.** 테마별 기본 성향 벡터가 이미 최댓값(5)으로 설정된 태그를, 이름 키워드 보정(예: "공원"→산책/휴식 +1)이 다시 그 태그에 더하려다 clamp에 막혀 무효화되는 구조적 결함. 관광지 후보군 안에서 성향 일치도가 사실상 전부 동률이 되어 최종 순위가 코사인 유사도가 아니라 관광지 ID 순으로 결정되고 있었다. `tourAttractionTags.js`의 테마별 기본값/키워드 보정 범위를 재조정해 수정 — 5곳 이상 후보군에서 벡터가 완전히 동일했던 경우가 6건 → 0건으로 감소.
- **[Important] `문화시설` 타입 관광지 19곳이 "기타" 테마로 잘못 분류.** KTO 분류 코드가 없는 관광지 중 `type` 필드("문화시설")를 코드에서 전혀 안 쓰고 있어, 도서관·공연장·문학관 등이 전부 "기타"로 뭉쳐 있었음(전체의 24%). `type` 필드를 규칙에 추가하고 키워드를 보강해 "기타" 비중을 13.3%로 낮춤.
- **[Important] "산" 이름 키워드가 너무 광범위해 일부 역사/문화 관광지를 자연으로 오분류.** (예: "둔산선사유적지"가 "둔**산**"에 매칭돼 역사가 아닌 자연으로 분류됨) 규칙 순서를 조정해 수정.
- **[환경] `package.json`의 `"test": "node --test src"` 스크립트가 이 개발 환경(Windows/Node 24)에서 실제로 동작하지 않음을 발견** — 디렉터리 인자를 재귀 탐색하지 않고 모듈로 취급해 `MODULE_NOT_FOUND` 오류. 명시적 글로빙(`"src/**/*.test.js"`)으로 수정.

수정 후 재리뷰 통과, 최종 전체 리뷰 클린 확인.

## 자가 점검

- **범위:** 원래 이슈 #14 본문에는 추천 로직을 "별도 이슈로 진행 예정"이라고 적어뒀으나, PDF가 같은 날 도착해 동일 브랜치에서 이어서 구현했다. PR 본문에 이 점을 명시할 것.
- **데이터 정확도:** 173곳 관광지의 테마/성향태그/동행적합도는 기획팀이 직접 태깅한 데이터가 아니라 규칙 기반 자동 생성이다(KTO 분류코드 + 이름 키워드). 100% 정확도를 목표하지 않았고, 실제 대표 사례 검증(뿌리공원·이응노 미술관·한밭교육박물관·국립 대전 현충원·한밭수목원 등)은 맞았지만 173곳 전체를 사람이 검수한 것은 아니다 — 추후 기획팀이 실제 태깅 데이터를 전달하면 `tourAttractionTags.js`를 교체하는 편이 정확도 면에서 더 낫다.
- **미해결/범위 외:** 그라데이션 디테일(흰색/노란색 비중 등)과 관광모아 UI 비주얼은 여전히 디자인 시안 도착 전 상태 — 시안이 오면 별도 이슈로 추가 조정 예정(사용자 결정).
