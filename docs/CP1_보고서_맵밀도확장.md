## 변경 파일

- **`src/config/regions.js`** — `bbox`, `districts`(5개 구), `kakaoKeywords`(빵집·베이커리·제과·제과점·도넛·케이크·디저트), `districtKeywords`, `specialtyQueries`(성심당 등) 추가. 기존 단일 `kakaoQuery` 제거.
- **`src/api/kakaoLocal.js`** — `buildKakaoQueries()`로 시 전역×구별 질의 19개 생성. 카카오 `rect`로 대전 bbox 한정, 응답을 bbox로 재필터, 쿼리당 3페이지 페이지네이션.
- **`src/api/normalize.js`** — dedup 2단계: ① 카카오 place id 1차 제거 ② 이름+좌표(소수 3자리 ≈ 111m 격자) 복합 키. 프랜차이즈 분점은 좌표로 분리 보존.
- **`src/hooks/useBakeries.js`** — `[bakeries]` 콘솔 로그: 수집 / 중복제거 후 / 구별 분포.

관광공사 병합 로직(관광공사 우선, 빈 필드만 카카오 보강)은 유지.

## 호출 비용

19쿼리 × 최대 3페이지 ≈ **57회/로드**. 카카오 일 쿼터(10만) 대비 안전.

## 자가 점검

- **데이터 계약:** `regions.js` 필드명 ↔ `kakaoLocal.js` 소비부 일치. `kakaoQuery` 잔존 참조 없음(grep 확인). Bakery 객체 형태 불변 → 지도 컴포넌트 드리프트 없음.
- **구조적 결함:** dedup 멱등. id제거 360 = 이름+좌표제거 360 → 다지점(뚜레쥬르·파리바게뜨 등) 뭉개짐 없음 확인.
- **경계:** rect + bbox 이중 필터로 대전 밖 0건.
- **결함 없음.**

## 검증 방법

- `npm run build` — 통과 (70 modules, ~450ms).
- 라이브 카카오 API 프로브로 수집 800 → bbox 800 → id제거 360 → 이름+좌표제거 360 확인.
- (브라우저 미검증) `npm run dev` 후 콘솔 `[bakeries]` 로그로 분포 확인 가능.
